# Pytae Future Enhancements & Design Blueprint

This document tracks vetted, agreed-upon architectural enhancements to be scheduled and implemented in future versions of Pytae.

---

## 1. Schema-Only Diffing via `-diff "<target>,schema"`

### Problem Statement
Comparing large datasets (e.g. multi-gigabyte or 10M+ row tables) currently requires full cell-by-cell data comparisons, key alignment, and numeric tolerance checks. When data engineers and analysts only want to detect schema drift, type widening, or column additions/removals, reading all row data is slow and unnecessary.

### Agreed Syntax
Extend the existing `-diff` specification parser rather than creating a separate command:
- **CLI**:
  ```bash
  pytae jan.parquet -diff "feb.parquet,schema"
  ```
- **REPL**:
  ```text
  pytae [jan: 1000x5]> -diff "feb,schema"
  # or with two explicit tables:
  pytae> -diff jan "feb,schema"
  ```

### Behavior & Output
- **Fast Metadata-Only Scan**: Reads only file metadata/schema without streaming all rows into memory.
- **Report Contents**:
  1. **Shape**: Row count diff, column count diff.
  2. **Column Changes**:
     - `+ Added in target`
     - `- Removed in target`
     - `= Common columns`
  3. **Type Drift**: Dtype changes for common columns (e.g. `Int32` -> `Int64`, `String` -> `Datetime`).
  4. **Null Count Comparison**: Summary of null count delta per column.
  5. **Skipped**: Completely bypasses cell value comparisons, row matching, and tolerance checks.
- **Zero Collision**:
  Avoids collision with the top-level `-schema` pipeline inspection command by keeping `schema` inside the target spec string (`"target,schema"`), perfectly matching existing options like `"target,on=id"` and `"target,tol=1e-3"`.

## 2. Schema DDL & Code Generation via `-schema [format]`

### Problem Statement
After inspecting a raw Parquet/CSV file, users often need to write boilerplate definitions for SQL databases, BigQuery tables, or API validation models. Pytae already knows the exact inferred schema types; transcribing them manually is tedious and error-prone.

### Agreed Syntax
Extend the existing `-schema` inspection command to optionally accept a target format:
- **CLI**:
  ```bash
  # Existing default tabular summary (Column, Type, Nulls, Unique)
  pytae data.parquet -schema

  # ANSI SQL CREATE TABLE DDL
  pytae data.parquet -schema sql

  # BigQuery Schema JSON / DDL
  pytae data.parquet -schema bq

  # Python Pydantic BaseModel definition
  pytae data.parquet -schema pydantic

  # JSON Schema standard definition
  pytae data.parquet -schema json

  # Copy generated DDL directly to clipboard
  pytae data.parquet -schema sql -o clip
  ```
- **REPL**:
  ```text
  pytae [df: 344x7]> -schema
  pytae [df: 344x7]> -schema sql
  pytae [df: 344x7]> -schema pydantic
  ```

### Type Mapping Specification
- **`sql`**: Maps Pytae/Polars dtypes to standard ANSI SQL:
  - `Int64` -> `BIGINT`
  - `Int32` -> `INTEGER`
  - `Float64` -> `DOUBLE PRECISION`
  - `String` -> `VARCHAR`
  - `Boolean` -> `BOOLEAN`
  - `Date` / `Datetime` -> `DATE` / `TIMESTAMP`
  - Respects nullability: columns with 0 nulls get `NOT NULL`.
- **`bq`**: BigQuery schema JSON format (`[{"name": "...", "type": "...", "mode": "REQUIRED|NULLABLE"}]`).
- **`pydantic`**: Python `BaseModel` class with typed fields and `Optional[...]` where nulls exist.

### Zero Collision
- `-schema` never takes column names, so format arguments (`sql`, `bq`, `pydantic`, `json`) have zero risk of colliding with column selectors.
- Bare `-schema` preserves 100% backwards compatibility with the existing summary table.

## 3. Core Architectural Principles (Re-affirmed)

1. **Keep REPL Lite**:
   - The REPL is a fast, interactive tabular scratchpad—not an execution engine for multi-file codebases or an inferior Python interpreter.
   - No ad-hoc script importing (`run file.py`) inside the session.
   - Replay pipelines into the REPL from the outside via `pytae -i <script.pt>`.
   - Graduate out of the REPL cleanly using `export pipeline.py` or `export pipeline.pt`.

2. **Strictly 1 and Only 1 Canonical Way**:
   - Deepen existing commands (`-diff`, `-schema`) rather than creating competing verbs (`-diff_schema`, `-profile`, etc.).
   - Disallow ambiguous synonyms and provide strict rejection pointers (`pytae: '<alias>' is not recognized; use '<canonical>'.`).

3. **Terminal-First & Fast**:
   - Distribution histograms are already built-in via `-hist COLUMN[:BINS]` (`pytae file -hist col`).
   - New features must remain zero-dependency, instantaneous, and terminal-friendly.
